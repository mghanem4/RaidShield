# Technical Decisions

## 2026-08-21

1. **Clean scaffold.** The repository contained only the authoritative specification, so there is no existing stack or local work to preserve.
2. **Compact modular monolith.** FastAPI, SQLAlchemy, Alembic, SQLite, React, TypeScript, and Vite follow the recommended stack. Detection stays in pure Python functions; source-specific parsing stays in adapters.
3. **Synchronous immediate replay.** Immediate replay is processed in-request for deterministic tests and direct result links. Paced replay uses a FastAPI background task. Both call the same ingestion service.
4. **No raw text when disabled.** Fingerprints and transient similarity inputs are calculated before persistence. With `STORE_RAW_TEXT=false`, no reversible text is stored. Alert feature snapshots retain aggregate cluster measurements only.
5. **Installation-scoped identities.** Full HMAC-SHA-256 digests are stored and only a short prefix is displayed. Raw source author identifiers are never added to domain objects or database rows.
6. **SQLite MVP concurrency.** The application uses short transactions and a background task only for paced replay. A production queue and PostgreSQL remain intentionally deferred.
7. **Local administrator authentication.** Mutations require a bearer token. Read APIs are intended only for services bound to localhost; this is not public-deployment authentication.
8. **Superseded: live-source exploration.** A signed live-input adapter was originally planned. Decision 18 removes all live-source behavior in favor of offline-only input.
9. **Local Python compatibility.** The specification targets Python 3.12+, while the provided workstation has Python 3.10. The package keeps a Python 3.12 container target and uses syntax/dependency bounds compatible with 3.10 so all local quality gates can be executed. This widens compatibility without changing runtime behavior.
10. **Offline frontend assets.** UI inspection prompted removal of a remote font import. The rendered application now uses local system fonts and makes no third-party asset request.
11. **Patched frontend toolchain.** Audits found advisories in React Router v6 and the original Vite/Vitest development toolchain. React Router 7.18.2, Vite 8.2.2, and Vitest 4.1.11 clear the full audit; component, type, build, and Playwright tests pass afterward.
12. **High confidence limitation.** High data confidence requires at least ten authors and all feature families, but not yet persistence across two adjacent windows. The stricter condition is documented and deferred rather than misrepresented.
13. **Superseded: source API versioning.** Versioned platform configuration was explored and is removed by Decision 18.
14. **Isolated E2E ports.** Playwright uses dedicated ports 8010 and 5174 with a test-only administrator token. It never reuses manually running development servers, preventing authentication mismatches with the owner's `.env` configuration.
15. **Authenticated text disclosure.** When `STORE_RAW_TEXT=true`, authenticated thread views and evidence exports decrypt locally stored text. With storage disabled, both retain the explicit `content hidden` placeholder. Exports remain identity-redacted and require the administrator token.
16. **Superseded: live payload compatibility.** Live payload parsing was explored and is removed by Decision 18.

## 2026-08-24

17. **Optional experimental local content triage.** A pinned `morit/arabic_xlm_xnli` adapter is available behind `CONTENT_DETECTOR_ENABLED=false`. It uses abstract review labels, safetensors, local-files-only runtime loading, sanitized failure behavior, and transient plaintext processing. Its evidence and provenance remain separate from coordination; only a signal above the configured threshold can prioritize an existing coordination alert, and a human review can override it. The default threshold is explicitly uncalibrated, Arabizi capability is unproven, safe replay fixtures are excluded unless organizer-authorized, and no autonomous action follows.
18. **Offline-only input.** The owner removed the live-platform scope. Strict offline JSON and bundled replay adapters now share normalized ingestion; all live-source routes, platform configuration, credentials, tests, proxy rules, and active setup documentation are removed. Imports are bounded, authenticated, processed in memory, and never retain filenames or raw bodies. Source IDs are dataset-scoped hashes and raw participant IDs remain transient.
19. **Safetensors-only model weights.** Both the one-time cache command and runtime model loader pass `use_safetensors=true`, preventing fallback to pickle-based model weights. Runtime remains local-files-only by default and pinned to an immutable model revision.
20. **Derived coordination graph.** A deterministic post-scoped graph connects pseudonymous participants using exact repeated-text fingerprints (45%), activity within 30 seconds (35%), and a shared reply target (20%), with a minimum combined edge strength of 0.25. A shared target alone is therefore insufficient. Connected components define visual clusters. The API exposes graph-local node IDs and short labels only, caps rendering size, persists no graph state, and explicitly avoids bot, identity, or intent claims. Redacted graph data is included in evidence JSON.
21. **Browser-only movable graph.** Native React/SVG pointer interactions provide draggable and pinnable nodes, canvas pan, cursor-centered zoom, keyboard node movement, reset, and an optional deterministic force-relaxation pass for unpinned nodes. No visualization dependency or layout persistence is added. Moving a node changes presentation only and cannot affect graph edges, detection scores, alerts, or exports.
22. **Separate transient reply context.** Both offline and replay adapters use one batch enrichment service to compare every reply with its direct parent and all siblings before plaintext is discarded. Persisted structural metadata includes timing/order and exact/near sibling repetition only. When the optional safetensors model is enabled, it ranks abstract parent–reply relations using transient text and persists scores/provenance without changing coordination, content review, priority, or human resolution. Context appears in threads, graph summaries, and redacted exports with explicit uncertainty language.
23. **Faithful per-comment evidence, not generated rationale.** Thread APIs publish only allowlisted classifier fields. Post and alert views combine those fields with already-authorized visible text and deterministic reply evidence, then state which top-ranked label met or missed the configured threshold. The panel explicitly disclaims hidden reasoning, probability, hate determination, and policy judgment.
24. **Transient multilingual semantic coordination.** A separate pinned `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` encoder compares `parent + reply` representations for different participants with matching reply roles and close timing. Safetensors and local-files-only loading are mandatory. Plaintext and vectors are discarded; persisted records contain hashed batch-local event references and abstract scores only. When available, semantic context contributes 20% to the alert feature score and 30% to graph edges, but cannot form a graph edge without timing, exact text, or a shared target. It remains experimental, uncalibrated, and non-determinative.
